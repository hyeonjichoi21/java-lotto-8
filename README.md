# java-lotto-precourse (week3)

## 구현할 기능 목록

- [ ]  로또 구입 금액 입력받기(1,000원 단위)
- [ ]  구입 수량 계산 후 로또 티켓 N장 발행 (1~45, 중복 없는 6개, 오름차순)
- [ ]  당첨 번호 입력받기(쉼표 구분 6개)
- [ ]  보너스 번호 입력받기(1개)
- [ ]  각 티켓과 당첨 번호 비교 → 일치 개수/보너스 여부 판정
- [ ]  등수 집계(1~5등) 및 총 수익 계산
- [ ]  수익률 계산(소수점 첫째 자리까지 반올림) 후 출력
- [ ]  예외 발생 시 `IllegalArgumentException` 던지고 `"[ERROR]"` 접두사로 메시지 출력 후 해당 입력부터 재진행

---

## ➡️ 입력

### 1) 구입 금액

- **검증 항목**
  - 정수인지
  - 1,000원 단위인지 (`amount % 1000 == 0`)
  - 1,000원 이상인지
- **허용 항목**: 앞뒤 공백(trim)
- **예외 항목**:
  - `[ERROR] 구입 금액은 1,000원 단위의 양수여야 합니다.`

### 2) 당첨 번호 (예: `1,2,3,4,5,6`)

- **검증 항목**
  - 쉼표 기준 6개
  - 모두 정수 & 범위 1~45
  - 중복 없음

- **허용 항목**
  - 쉼표 뒤에 공백

- **예외 항목**:
  - `[ERROR] 당첨 번호는 1부터 45 사이의 중복되지 않은 6개여야 합니다.`

### 3) 보너스 번호 (예: `7`)

- **검증 항목**
  - 정수 & 범위 1~45
  - 당첨 번호와 중복 불가
- **예외 항목**:
  - `[ERROR] 보너스 번호는 1부터 45 사이이며 당첨 번호와 중복될 수 없습니다.`

---

## 🍀 진행/로직

- **발행**
  - 구입 수량 = `amount / 1000`
  - 각 티켓: `Randoms.pickUniqueNumbersInRange(1, 45, 6)` → 오름차순 정렬
- **채점**
  - 일치 개수 계산
  - 보너스 일치 여부
  - 등수 매핑
    - 1등: 6개
    - 2등: 5개 + 보너스
    - 3등: 5개
    - 4등: 4개
    - 5등: 3개
    - 그 외: 미당첨
- **집계**
  - 등수별 개수, 총 상금(등수 상금 × 개수)
  - 수익률 = `(총 상금 / 구입 금액) * 100` → 소수점 둘째 자리 반올림

## 출력 ➡️

### 1) 발행 결과

- 예)

    ```
    8개를 구매했습니다.
    [8, 21, 23, 41, 42, 43]
    [3, 5, 11, 16, 32, 38]
    ...
    ```

- **형식**: 각 줄마다 `[a, b, c, d, e, f]` (오름차순)

### 2) 당첨 통계

- 예)

    ```
    당첨 통계
    ---
    3개 일치 (5,000원) - 1개
    4개 일치 (50,000원) - 0개
    5개 일치 (1,500,000원) - 0개
    5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
    6개 일치 (2,000,000,000원) - 0개
    총 수익률은 62.5%입니다.
    ```

- **주의**: 문구/괄호/쉼표/공백/줄바꿈 그대로 맞추기

## 예외 처리 정책

- 모든 사용자 입력 검증 실패 시 `IllegalArgumentException` 사용
- 에러 메시지는 lotto.util.ErrorMessage 클래스에 정의된 상수를 활용한다.
  - 에러 메시지는 항상 `"[ERROR]"`로 시작
  - 예시
    - `ErrorMessage.INVALID_AMOUNT` → `[ERROR] 구입 금액은 1,000원 단위의 양수여야 합니다.`
    - `ErrorMessage.DUPLICATE_BONUS` → `[ERROR] 보너스 번호는 당첨 번호와 중복될 수 없습니다.`
- 예외 발생 시, 해당 입력 단계뿌터 다시 입력을 받는다. 
  - 구입 금액 입력 오류 시 → 금액부터 재입력
  - 당첨 번호 입력 오류 시 → 당첨 번호부터 재입력
  - 보너스 번호 입력 오류 시 → 보너스 번호부터 재입력
- `IllegalStateException` 등 모호한 예외는 쓰지 않음
  - 입력 값이 잘못된 경우에는 항상 `IllegalArgumentException`만 사용한다.

## 설계 메모 (간단)

- **상수**: `PRICE=1000`, `MIN=1`, `MAX=45`, `SIZE=6`
- **패키지 방향**

    ```
    lotto
     ├─ app      : Application, Controller
     ├─ domain   : Lotto, WinningNumbers, Rank, Money
     ├─ infra    : RandomNumberPicker (missionutils 래퍼)
     ├─ view     : InputView, OutputView
     └─ util     : 파싱/검증 보조(필요 시)
    
    ```

- **규칙 반영**
  - 하드 코딩 금지(의미 있는 상수)
  - `else/switch` 미사용 → early return
  - indent ≤ 2, 메서드 ≤ 15라인
  - UI(System.in/out) 분리(테스트 제외)
  - 클래스 작성 순서: 상수 → 필드 → 생성자 → 메서드

## 테스트 (도메인 중심, 작게 쪼개기)

- `Lotto`
  - 6개 아닐 때 예외
  - 범위 밖/중복 시 예외
  - 내부 오름차순 보장
- `WinningNumbers`
  - 보너스가 당첨과 중복이면 예외
- `Rank`
  - (6,*)=1등 / (5,+보너스)=2등 / (5)=3등 / (4)=4등 / (3)=5등 / 나머지 미당첨
- 채점/집계
  - 일치 수/보너스 판별
  - 등수별 개수 집계
  - 수익률 한 자리 반올림(%.1f%%) 검증
- 예외 메시지 접두사 `"[ERROR]"` 확인

> UI 테스트는 제외. 난수는 래퍼로 분리해 더블 주입 가능하게.
